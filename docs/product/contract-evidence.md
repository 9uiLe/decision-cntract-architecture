# 判断済みの値が使える時点

同じ参加者や予約 ID を持つ値でも、表す事実と使える操作は異なります。契約の正本は Kotlin の公開宣言です。 [資格の証明書](../../product/eligibility-core/src/commonMain/kotlin/example/eligibility/core/Certificate.kt) · [予約の受付対象と操作券](../../product/reservation-core/src/commonMain/kotlin/example/reservation/core/Evidence.kt) · [受付の操作券](../../product/checkin-core/src/commonMain/kotlin/example/checkin/core/State.kt)

| 契約 | 発行者と対象 | 意味と利用先 | 再確認と再利用 |
| --- | --- | --- | --- |
| 参加者集合 | 予約 Core が開催回に対する参加者を確認する | 空でなく、同じ参加者を含まない構造条件。資格や予約可否は別の判断 | 構造条件は時刻に依存しない。参加者の変更後は、変更後の集合で予約内容を確認する |
| `EligibilityCertificate` | 参加資格 Core が参加者と必要資格の組を確認し、確認時刻を記録する | 確認時点の資格充足。予約 Core は対象と必要資格が一致する確認結果を使う | 初回送信と再試行では資格 Core が現在の観測を取り直す。証明書を再利用する場合も、以前の確認だけで送信しない |
| `ConfirmedDraft` | 予約 Core の確認操作が現在の開催回と参加者に対して発行する | 利用者がその内容を確認した事実。予約作成前の入力 | 内容を変更したり確認し直したりしたら、新しい値を使う。送信は現在の確認と照合し、送信期限や資格を確かめる |
| `ReservationRecord.Reserved` | 予約 Core がサービスの成立を確認して記録する | その予約が成立した履歴。成立時に必要だった資格条件を保持する | 資格失効だけでは履歴を変えない。受付に使う時点で、取消や利用停止などの現在状態を確認する |
| `ReservationAdmission` | 予約 Core が成立時に予約と参加者の組を確定する | 受付を試みる予約と参加者を指定できる。成立時に必要だった資格条件を保持する | 受付を試みるたび、予約 Core へ現在の状態を照会する |
| `CurrentAdmission` | 予約 Core の `admission` がサービスの現在状態を照会したあとに発行する | `observedAt` で利用できると確認した予約と参加者。来場受付 Core が受付可否の判断に使う | 今回の照会時刻の区間と対象の一致を確認する。次の受付では照会し直す |
| 照会・再試行・取消の操作券 | 操作を所有する Core が、元の要求、未成立の操作、または予約に対して発行する | 結果に対して許可された操作を選べる | 操作時に現在の状態と一致するかを確認する。照会には元の要求を使い、新規要求の ID は明示的な再試行で発行する |

操作券や確認済みの値は発行元のモジュール境界内で構築します。外から直接生成できないことは、内部可視性を与えていない独立した Kotlin の利用モジュールで検証します。値が現在の状態に合うかは、境界値、別の参加者、古い操作、重複要求のテストで確かめます。保存・復元を扱う場合は、履歴を復元してから現在の操作前提を発行し直します。プロセス終了後の復元は課題 G で扱います。[Kotlin の可視性](https://kotlinlang.org/docs/visibility-modifiers.html)

## 判断を支える処理

| 処理 | 所有者 | 検証する性質 |
| --- | --- | --- |
| 資格のコードと期限を外部入力から読む | `:adapter-simulator` の `QualificationDecoder` | 未知のコードや不正な値から有効な資格を発行できない。課題 L の固定入力でも変換を比較する |
| 観測から資格充足を判断する | `:eligibility-core` | 有効期限の等号は無効。課題 H の一時停止にも明示的に対応する |
| 資格確認と予約対象を対応付ける | `:reservation-core` | 対象者と種別、参加者集合の一致。条件不充足と確認不能をそれぞれ扱う |
| 予約の現在状態を受付向けの結果へ変換する | `:reservation-core` | 取消済みの予約を拒否し、課題 J では利用停止の理由を明示する |
| 受付の対象、時刻、重複を確かめる | `:checkin-core` | 過去の成立だけでは受け付けない。課題 I では対象者と資格の種別が一致する証明だけを受け入れる |
| Port の実装を各 Core に接続する | `:shared` の組み立て | 呼び出し元の制約とモジュール依存を検証する |

型検査が受け持つのは、たとえば予約要求の操作券を受付照会に渡せないことです。異なる参加者について発行された同じ型の値を取り違えないためには、各操作が対象の一致を確認します。検査の実行結果は [検証記録](verification-results.md) にあります。

資格 Adapter は外部データの形式とコードを読み、資格の保有と期限を観測として渡します。未知のコード、壊れた期限、重複するフィールドは確認不能です。サービスが明示した未取得とは区別します。読み取った期限を今回の業務判断に使えるかは参加資格 Core が決めます。

## 判定時刻

要資格予約では、参加資格 Core が全員分の観測を取り直してから判定時刻を読みます。予約 Core は、再確認した時刻が全員分で一致し、今回の確認の時間内であることを確かめます。その時刻の資格充足と新規送信期限を確認し、送信の直前にも受付が終了していないことを確かめます。課題 I の要資格受付は、対象参加者の再確認時刻を受付時間の判断にも使います。

時刻の照合は、照会の前後の区間から外れる結果を拒否します。同じミリ秒に発行された値の再生を、時刻だけで区別することはできません。`:shared` は毎回外部状態を照会する Core 同士を接続します。照会で使う時計は同じ時刻系で揃えます。資格の判定後に期限を迎えた場合は判定時点の結果を使い、開催開始を迎えた場合は予約を送信しません。

予約の取消や受付の条件は時間とともに変わります。開催72時間前に成立し、48時間前に取り消された予約の古い参加者情報を、開催20分前の受付時間内に渡した場合も、現在の予約状態を照会します。取消済みであれば受付要求も受付記録も増えません。送信や受付を重複させないため、各 Core が操作の識別子と現在の進行状態を照合します。
