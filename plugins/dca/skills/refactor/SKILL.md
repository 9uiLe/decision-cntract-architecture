# refactor

対象フローの DCA への段階移行を、依頼された範囲で進める。

## 使う場面

- DCA が対象フローの課題に役立つかを判断したい。
- 部分適用を含めた移行計画を作りたい。
- 合意した計画のうち、依頼した変更を実施したい。
- 中断した移行を、合意と検証の有効性を確かめながら再開したい。

## 手順

最初に、依頼が適用判断、計画、変更のどこまでを含むかを確認する。含む範囲を決められないときは、変更を含まない範囲として扱い、利用者に確認する。外部記録の資料の「作業の始め方」に従い、保存先、既存のフロー、現在の変更対象を確かめる。

1. 適用判断。課題と DCA の適用条件を照合する。全面適用、部分適用、適用不要を比べる。未決の事項は、`interview` で解消するよう利用者に案内する。
2. 計画。次を決める。
   - 保つ振る舞いと保証
   - 移す判断
   - 変える契約
   - 移行の単位
   - 各段階の検証
   - 終了条件

   一時的な構造を置くときは、その目的と撤去の条件も決める。
3. 変更。コードの変更が明示された依頼に含まれているときだけ、指定された移行の単位を変更する。計画だけの依頼では、コード、設定、依存関係を変更しない。
4. 検証。変更した段階の契約と振る舞いを確認する。検証の前後で識別情報を作り、根拠と未確認の事項を記録する。次の段階へ進む条件と完了条件は、段階移行の共通資料に従う。
5. 再開。過去の合意を保ち、コード、依存関係、仕様の変化に応じて、検証の有効性を確かめる。古い検証結果だけで、現在の状態を保証しない。

調査が要るときは、`map` と `scan` の結果があれば、現在の対象と一致するかを確かめて使う。なければ、依頼された作業に必要な範囲を、この Skill で調べる。

構造の移行中に、仕様の変更が要ると分かったときは、変更を止める。別の論点と別の変更の単位として、利用者に示す。

## 出力

依頼の範囲に応じて、次を返す。

- 適用判断
- 移行計画
- 変更の内容
- 検証結果
- 未完了の事項
- 保存先、選択元、新しい記録かどうか、現在の変更対象

記録の形式と保存は、情報モデルと外部記録の共通資料に従う。

## 完了条件

- 適用判断の依頼は、適用範囲と理由、保留事項が示されている。
- 計画の依頼は、段階、保つ保証、検証方法、終了条件が具体的に決まっている。
- 変更の依頼は、依頼された段階の変更と必要な検証が対応付けられ、結果と未確認の事項が示されている。

対象範囲の移行の完了は、同じ契約を迂回する経路の解消と、撤去を合意した一時的な構造の扱いを含む終了条件に照らして判断する。契約を迂回しない旧い入口と、正当な履歴データの参照経路は、古いことだけを理由に撤去の対象にしない。

## 境界

- 計画への合意だけで、依頼されていない実装を始めない。
- 仕様の変更を構造の移行に紛れ込ませない。
- DCA の形に合わせること自体を目的にしない。適用不要の結論も扱う。
- テストの数やファイルの形だけで、保証が成り立つと判断しない。
- 他の Skill の事前の実行を、開始の条件にしない。
