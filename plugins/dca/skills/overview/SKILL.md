# overview

dca 自体の構成を、根拠付きの SVG で示す。

## 使う場面

- dca の利用者や保守者が、全体の構成を理解したい。
- Skill、責務、共通資料、成果物の関係を変更したい。
- Plugin を変更したので、構成図を更新したい。
- 登録情報と構成図のずれを確認したい。

## 読む資料

- [構成図の入力と view データ](references/view-data.md)

## 手順

利用者が構成図を見るだけのときは、パッケージの `docs/overview.svg` を表示して説明する。再生成は、Plugin を管理するリポジトリで保守のために行う。

1. Plugin の保守で再生成するときは、保守用の作業場所を確認する。導入先のコードと外部記録は読まない。
2. `scripts/dca_overview.py extract` で、view データを作る。入力は、manifest、`SKILL.md`、`agents/openai.yaml`、参照資料である。スクリプトは、この SKILL.md から見て `../../scripts/dca_overview.py` にある。
3. 抽出した関係を、Skill の定義と照らして確認する。根拠が曖昧な関係は、線にせず、不足している事項として示す。
4. `render` で、view データから SVG を描く。`check` で、入力の hash、登録集合、参照の存在、再描画の一致を検査する。測定値を作り直すときだけ、`metrics --font <Noto Sans CJK JP 2.004 の OTF>` を使う。
5. SVG を実際に表示し、日本語、ラベルの重なり、見切れ、凡例と線の区別を確認する。
6. 前回との差分を説明する。差分がないときも、確認したことを結果に残す。

## 出力

- dca 自体の構成を示す SVG（`docs/overview.svg`）。
- 根拠付きの view データ（`docs/overview.view.json`）。
- 関係の種類を読める凡例。
- 検査の結果。
- 不足している登録情報と、根拠が足りない関係。図に、根拠のない線を足さない。

## 完了条件

- 図の Skill の集合が、実際の登録集合と一致している。初期の構成では `overview` 自身を含む 8 件である。
- 共通資料、実行環境、成果物の関係に根拠がある。
- 入力の hash、view データ、SVG の対応を確認し、保持している view データから再描画した結果が一致している。
- SVG を表示して、日本語のラベルと線を確認し、前回との差分と未確認の事項を説明できる。

## 境界

- 導入先の業務判断とコードの構造は、`map` が扱う。導入先の調査、合意、検証の記録を、構成図に混ぜない。
- 図を読みやすくするために、存在しない依存を補わない。
- 生成された SVG、preview、過去の view データを、構成や思想の元として扱わない。
- 検査が通ったことは、関係の意味が正しいことを示さない。意味と表示は、確認して判断する。

## 他の Skill との関係

- 生成 artifact:overview-view: 入力の hash と根拠を持つ view データ
- 生成 artifact:overview-svg: dca 自体の構成図
