# 構成図の入力と view データ

overview が、dca の実際の登録情報から根拠付きの構成図を作り、変更のたびに再確認するための資料。

## 図の対象

図は、dca 自体の構成と、Skill 同士の関係を表す。導入先のコードは読まない。導入先のアーキテクチャ図や調査結果は作らない。

Skill のノードは、実際の登録集合から取り出す。初期の設計では `guide`、`overview`、`map`、`scan`、`interview`、`refactor`、`lint`、`principles` の 8 件で、`overview` 自身を含む。図にだけある Skill と、登録済みなのに図にない Skill を許さない。

共通資料、同梱思想、Claude Code と Codex CLI、生成する成果物も表示する。これらは Skill のノードと種類を分け、Skill の件数に含めない。成果物には保存先の区分を付け、Plugin の保守成果物と、導入先の記録を区別する。

## 入力

入力は明示的に列挙する。

| 入力 | 用途 |
| --- | --- |
| `plugin.json` と `.claude-plugin/plugin.json` | Plugin の識別情報、登録の経路、host の確認 |
| `skills/<name>/SKILL.md` | Skill 名、責務の要約、読む資料、他の Skill との関係 |
| `skills/<name>/agents/openai.yaml` | 登録と起動方針の整合の確認 |
| SKILL.md の「読む資料」が指す同梱の参照資料 | 参照先の存在の確認 |
| 描画規則、renderer、フォントの版 | 再現できる SVG の生成 |

次のものは入力に含めない。生成済みの SVG、preview、cache、過去の view データ、導入先のリポジトリ、調査記録、合意記録。

構成と思想の元になるのは、manifest、Skill の定義、同梱する参照資料である。view データは、これらから作る派生物である。view データだけを編集して、定義の変更の代わりにしない。

## 関係の宣言

線は、SKILL.md の定型の節から取り出す。近くにあることを理由に、Skill 同士を結ばない。

「読む資料」の節にある Markdown のリンクは、参照の線になる。リンク先は、同梱の参照資料のパッケージ相対パスに解決する。

「他の Skill との関係」の節の各行は、次の形で宣言する。

```text
- <種類> <対象の種別>:<対象>: <ラベル>
```

| 種類 | 表す内容 |
| --- | --- |
| 案内 | ある Skill が、利用者の目的に応じて別の Skill を案内する |
| 参照 | ある Skill が、別の Skill またはその同梱思想を、判断の根拠として使う |
| 呼び出し | 定義された条件のもとで、ある Skill が別の手順を呼び出す |
| 引き継ぎ | ある Skill の出力を、条件を満たしたときに利用者を介して別の Skill が受け取る |
| 生成 | Skill や補助処理が、定義された成果物を生成する |
| 実行環境 | Skill や補助処理が、対象の host で利用される |

対象の種別は、`skill`（Skill の名前）と `artifact`（成果物の識別子）である。`参照` は「読む資料」の節から取り出すので、この節には書かない。`実行環境` は manifest から取り出す。

明記されていない順序を固定の実行順として描かない。利用できる組み合わせを、必須の遷移に変えない。宣言のない関係は、線にしない。

## 成果物

「他の Skill との関係」で `artifact` として宣言する対象は、次の表で定義する。表の行が、成果物のノードの表示名、保存先の区分、説明になる。

| 識別子 | 表示名 | 保存先の区分 | 説明 |
| --- | --- | --- | --- |
| `external-record` | 外部記録 | 導入先の記録 | 対象リポジトリの外に置く、調査、合意、進捗、検証結果 |
| `overview-view` | 構成図の view データ | Plugin の保守成果物 | 入力の hash と根拠を持つ、構成図の元データ |
| `overview-svg` | 構成図の SVG | Plugin の保守成果物 | Plugin 自体の構成を示す図 |

## 生成の二段階

### 定義から view データを作る

この Plugin の `scripts/dca_overview.py` の `extract` が、上の入力を読み、ノードと線に根拠のパッケージ相対パスと節を付けて view データを作る。関係の意味は、宣言した行に書かれたとおりである。宣言が実際の責務を正しく表しているかは、レビューで確認する。

### view データから SVG を描く

`render` が、view データを正規化し、固定の描画規則と renderer で SVG を描く。描画の段階では、Skill の責務や関係を新たに推測しない。同じ view データ、描画規則、renderer の版、フォントの測定値からは、同じ SVG を生成する。

## view データに持たせる情報

| 情報 | 要件 |
| --- | --- |
| 形式の版 | データ形式の変更を識別できる |
| Plugin の識別情報 | 名称と版が manifest と一致する |
| 入力 | 入力ファイルの相対パスと内容の hash を持つ |
| 登録集合 | 対象の Skill の集合を明示する |
| ノード | 種類、安定した ID、表示名、短い責務、根拠のパスと節を持つ。Skill では登録名と一致する |
| 線 | 始点、終点、関係の種類、ラベル、根拠のパスと節を持つ |
| 描画条件 | renderer、描画規則、フォントの識別を持つ |

ノードと線の並びは正規化する。ノードと線の ID を安定させる。現在日時、乱数、作業者名、環境に依存する絶対パスを入れない。無関係な再生成で差分を増やさない。

## 検査とレビュー

| 方法 | 確認すること |
| --- | --- |
| 機械検査 | view データに記録した入力の hash が、現在の入力と一致する |
| 機械検査 | 図の Skill ノードの集合が、実際の登録集合と一致する |
| 機械検査 | 線の両端が存在し、ノードと線の根拠の参照先がパッケージ内にある |
| 機械検査 | 保持している view データから再生成した SVG が、保持している SVG と一致する |
| 意味のレビュー | 責務の要約、線の意味、条件、根拠が、実際の定義を正しく表している |
| 表示のレビュー | 日本語が読める。ラベルが重ならない。見切れがない。線と凡例を区別できる |

参照先が存在することと、その参照が関係を裏付けることは、別に確認する。機械検査が通っただけで、意味のレビューを終えたことにしない。

SVG は実際に表示して確認する。ソースの差分だけで表示の品質を判定しない。

## 表示の方針

- 領域は、配置、余白、見出しで区分する。入れ子や近接で関係を示せるものに、説明のラベルを足さない。
- 関係の種類は、凡例と線のラベルの文言でも示す。色だけで区別しない。
- Skill のノードと、共通資料、同梱思想、host、成果物のノードは、見た目で区別する。
- 保存先の区分（Plugin の保守成果物か、導入先の記録か）を成果物のノードに表示する。
- 日本語のフォントは Noto Sans CJK JP 2.004 に固定する。文字の幅は、このフォントの測定値から計算する。

## 変更があったとき

Plugin を変更したときは、`extract` と `render` で view データと SVG を更新する。SVG の差分と表示を確認し、ノードの増減、線の追加と削除、ラベルの変化に説明できない差分がないことを確かめる。再生成して差分がないときも、その確認の結果を残す。
