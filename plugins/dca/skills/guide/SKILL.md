# guide

利用者の目的を一つ選び、使う Skill を一つ案内する。

## 使う場面

- DCA で何を確認すればよいか分からない。
- 既存フローの構造を理解したい、問題を探したい、未決の仕様を決めたい、移行を進めたい。
- 中断した作業を再開したい。特定の一工程だけを使いたい。

利用者が Skill を指定しているときと、依頼が一つの Skill で足りると分かっているときは、guide を挟まずにその Skill を使う。

## 使わない場面

- Kotlin の文法や、一般的な実装の質問。
- DCA と無関係な、単純な修正。

これらでは DCA の調査や移行を始めず、依頼の範囲を守る。

## 読む資料

- [外部記録](../principles/references/common/record-storage.md)。既存の記録があるときに「再開」を読む。

実行ホストは Claude Code と Codex CLI、コード移行の対象は Kotlin/JVM と KMP である。SwiftUI で操作が画面の更新から失われる問題は、原則の確認を `principles`、経路の調査を `scan`、検査の提案を `lint` で扱う。Swift 全般の自動移行や検査の導入は対応範囲外である。

## 手順

1. 依頼から、利用者が最初に得たい成果を一つ決める。成果が複数に読めるときは、どれを先に得たいかを一問だけ尋ねる。
2. リポジトリ、フロー名、既存の外部記録の有無など、調べれば分かる事実は調べる。尋ねない。記録の有無は `dca_state.py where` と `list` で確かめる。
3. 既存の外部記録があるときは、合意の内容と検証結果の有効性を別々に確認する。全工程をやり直す案内にしない。
4. 下の表から、目的に合う Skill を一つ選ぶ。
5. 案内を返す。

## 目的と Skill

| 利用者の目的 | Skill |
| --- | --- |
| 対象フローの判断、契約、状態、副作用を理解したい | `map` |
| 根拠付きで、問題と不足している情報を見つけたい | `scan` |
| 方針や仕様の未決事項を解消したい | `interview` |
| DCA を適用するか判断したい。移行を計画したい。依頼した変更を進めたい | `refactor` |
| 機械で検査できるルールを調べて提案してほしい | `lint` |
| DCA の原則と、必須と任意の区別を確認したい | `principles` |
| dca 自体の構成と、成果物の関係を確認したい | `overview` |

部分適用や適用不要という結論も、成果として扱う。その判断は `refactor` が扱う。

呼び出し方は、Claude Code では `/dca:<Skill 名>` とする。Codex CLI では `/skills` を開くか `$` を入力し、`dca:<Skill 名>` を選ぶ。`guide` 以外の Skill は、利用者が明示して選んだときだけ動く。

## 出力

次を短く返す。

- 推奨する Skill と、その理由。
- 対象の範囲と、依頼の範囲。
- その Skill に渡す入力。
- その Skill で得られる成果物。
- 他の経路も妥当なときは、それぞれを選ぶ条件。

## 完了条件

利用者が、次に何をするか、その Skill で何を得るか、どこまでが依頼の範囲かを判断できる。案内の先にある工程を実行したことは、完了条件に含めない。

## 境界

- 案内のために、他の Skill を実行しない。Skill を順に実行しない。
- 思想の定義、詳細な調査、設計上の判断、コードの変更は、それぞれの Skill が行う。
- 目的を一つに決められないときは、Skill を一つに絞らず、選ぶ条件を示して利用者に委ねる。

## 他の Skill との関係

- 案内 skill:map: 対象フローの判断、契約、状態、副作用を理解したいとき
- 案内 skill:scan: 根拠付きで問題と不足している情報を見つけたいとき
- 案内 skill:interview: 方針や仕様の未決事項を解消したいとき
- 案内 skill:refactor: 適用判断、移行計画、依頼した変更を進めたいとき
- 案内 skill:lint: 機械で検査できるルールを提案してほしいとき
- 案内 skill:principles: 原則と、必須と任意の区別を確認したいとき
- 案内 skill:overview: dca 自体の構成と、成果物の関係を確認したいとき
