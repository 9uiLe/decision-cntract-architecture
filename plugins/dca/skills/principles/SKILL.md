# principles

同梱する DCA の思想と、その適用条件、必須と任意の区別、共通手順の所在を説明する。

## 使う場面

- DCA を初めて使う人が判断の基準を理解したい。
- map、scan、interview、refactor、lint が適用する原則を確認したい。
- 必須の制約と、状況に応じて選べる設計手段を区別したい。
- 思想の更新が、dca の手順や評価に与える影響を確認したい。

## 読む資料

- [同梱思想の索引](references/index.md)

作業に必要な行が指す資料だけを読む。全資料を通して読まない。

## 手順

1. 作業の内容から、必要な原則と適用条件を特定し、該当する同梱資料を読む。
2. 原則の根拠と、dca が加える運用上の手順を区別する。思想に書かれていない判断を、その思想が必須としているように説明しない。
3. 適用する対象の必須の原則と、任意の設計手段を明示する。部分適用では対象外になる範囲も明示する。
4. 用語と原則の意味は、同梱資料の記述を引いて説明する。対象フロー固有の合意は、外部記録の側に残す。
5. 共通手順は、索引の「共通資料」に挙げたファイルを示す。各 Skill の手順に複写して再説明しない。
6. 思想の変更が、原則の分類、各 Skill の判断、検証の条件に影響するときは、更新する対象を示す。

## 出力

- 対象の作業に必要な原則、適用条件、必須と任意の区別。
- 各原則の根拠（同梱資料と出典の記号）。
- 共通手順の参照先。
- 定義がない、または解釈が分かれる事項。追加の調査と、利用者の判断を分けて示す。

## 完了条件

各原則について、出典と適用範囲が分かる。任意の選択を違反として扱わずに、後続の作業を進められる。

## 境界

- 導入先の仕様を決めない。
- 原則を説明しただけで、対象フローの適合や検証の完了を宣言しない。
- 現状の対応付けは `map`、問題の調査は `scan`、未決の合意は `interview`、変更は `refactor`、検査の提案は `lint` が行う。

## 他の Skill との関係

この Skill から他の Skill や成果物への関係は宣言しない。
